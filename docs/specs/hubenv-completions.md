# `hubenv completions` — Behavior Specification

> Reverse-engineered spec. Derived from the implementation in
> `nb_wrangler/hubenv/completions_cmd.py` and `nb_wrangler/hubenv/completions.py`.
>
> Verified against `tests/hubenv/test_e2e.py`.

---

## 1. Purpose

`hubenv completions <shell>` prints a **static** shell-completion script for
`hubenv` — no `argcomplete` or other runtime dependency. The script is a
pure function of a **hard-coded command tree** in `completions.py`; the user
sources or `eval`s it to get tab-completion for `hubenv`'s sub-commands.

The command tree is the *source of truth* for what completions suggests, and
it must match the actual `argparse` tree (RE-06 resolved: the tree was
flattened to all **20 top-level verbs**, with env verbs at the top level —
`hubenv create`, not `hubenv env create`).

---

## 2. Command synopsis

```
hubenv completions <shell>
```

where `<shell>` ∈ {`bash`, `zsh`, `fish`} (argparse `choices`).

---

## 3. Arguments

| Argument | Required / Default | Description |
|---|---|---|
| `<shell>` | required, positional, one of `bash`/`zsh`/`fish` | The shell to generate completions for. |
| global flags | — | `-q/--quiet`, `--verbose`, `--debug`, `--color`, `--log-times`,
  `--reset-log` (see [`hubenv-common.md`](hubenv-common.md) §3). |

---

## 4. Execution paths

1. **Parse** `hubenv completions <shell>`; `<shell>` is one of `bash`/`zsh`/`fish`
   (argparse enforces).
2. `script = completions.generate_completion(<shell>)`:
   - `bash` → `_gen_bash()`;
   - `zsh` → `_gen_zsh()`;
   - `fish` → `_gen_fish()`.
3. **If `script is None`** (unsupported shell — unreachable via the parser
   `choices`, but the code path exists):
   `Unknown shell '<shell>'. Supported: <comma-joined supported shells>`
   (stderr) → exit **1**.
4. **Otherwise** → `print(script, end="")` to stdout → exit **0**.

The script is the *only* stdout; it is written with `end=""` so the script's
own final newline is preserved exactly.

## 5. The command tree (static, in `completions.py`)

### 5.1 Top-level verbs (20)

These are completed at the *first* position (after `hubenv`):

```
create, save, restore, ls, info, install, uninstall, relock,
rm, ensure, register, unregister, activate, deactivate,
export, status, doctor, var, data, completions
```

### 5.2 Group sub-commands (3 groups)

| Group | Sub-commands |
|---|---|
| `var` | `add`, `rm`, `ls` |
| `data` | `ls`, `download`, `unpack`, `pack`, `clean` |
| `completions` | `bash`, `zsh`, `fish` |

### 5.3 Descriptions (for fish / zsh)

A hard-coded `_FISH_DESCRIPTIONS` dict maps each top-level verb to a short
description (e.g. `create` → "Create a new environment"); `_FISH_SUBCODESCRIPTIONS`
maps each sub-command to a description (e.g. `var add` → "Add or update env
vars").

## 6. The three scripts

### 6.1 Bash

Pure `COMP_WORDS` / `COMP_CWORD` parsing (no `bash-completion` package needed):

```bash
# bash completion for hubenv
# Generated by nb_wrangler.hubenv.completions — do not edit by hand.

if [ -n "$BASH_VERSION" -o -n "$ZSH_VERSION" ]; then
    hubenv_completion_function() {
        local cur prev words cword
        cur="${COMP_WORDS[COMP_CWORD]}"
        prev="${COMP_WORDS[COMP_CWORD-1]}"
        cword=$COMP_CWORD

        local top="create save restore ls info install uninstall relock rm \
ensure register unregister activate deactivate export status doctor var \
data completions"

        local var_cmds="add rm ls"
        local data_cmds="ls download unpack pack clean"
        local completions_cmds="bash zsh fish"

        if [ $cword -eq 1 ]; then
            COMPREPLY=( $(compgen -W "$top" -- "$cur") )
            return 0
        fi

        if [ $cword -eq 2 ]; then
            case "$prev" in
                var) COMPREPLY=( $(compgen -W "$var_cmds" -- "$cur") ) ;;
                data) COMPREPLY=( $(compgen -W "$data_cmds" -- "$cur") ) ;;
                completions) COMPREPLY=( $(compgen -W "$completions_cmds" -- "$cur") ) ;;
            esac
            return 0
        fi
    }

    complete -F hubenv_completion_function hubenv
fi
```

(Exact whitespace/formatting varies slightly per generation; the structure is
fixed.)

### 6.2 Zsh

Native zsh completions using `_describe` and `compadd` (no `bashcompinit`):

```zsh
#compdef hubenv
# zsh completion for hubenv
# Generated by nb_wrangler.hubenv.completions — do not edit by hand.

_hubenv() {
    local state line

    _arguments -C '1: :->cmd'

    case $state in
        cmd)
            _describe 'command' commands=(
                "create:Create a new environment"
                "save:Pack a live environment into a pantry archive"
                "restore:Unpack a saved environment and register kernel"
                "ls:List live envs and pantry shelves"
                …
                "var:Manage environment variables"
                "data:Manage data archives"
                "completions:Print shell completion scripts"
            )
            ;;
    esac

    if [ $CURRENT -eq 2 ]; then
        case $line[1] in
            var) compadd -a -- (add rm ls) ;;
            data) compadd -a -- (ls download unpack pack clean) ;;
            completions) compadd -a -- (bash zsh fish) ;;
        esac
    fi
}
_hubenv "$@"
```

### 6.3 Fish

Fish `complete` directives, one per top-level verb and one per sub-command:

```fish
# fish completion for hubenv
# Generated by nb_wrangler.hubenv.completions — do not edit by hand.

complete -c hubenv -n "__fish_use_subcommand" -a create -d "Create a new environment"
complete -c hubenv -n "__fish_use_subcommand" -a save -d "Pack a live environment into a pantry archive"
…
complete -c hubenv -n "__fish_seen_subcommand_from var" -a add -d "Add or update env vars"
complete -c hubenv -n "__fish_seen_subcommand_from var" -a rm -d "Remove env vars by glob"
complete -c hubenv -n "__fish_seen_subcommand_from var" -a ls -d "List env vars defined for an environment"
complete -c hubenv -n "__fish_seen_subcommand_from data" -a ls -d "List data archives for an environment"
…
```

## 10. What is NOT done (out of scope for the current implementation)

- **Installation is the user's job** — the command only *prints* the script;
  the user sources / writes it themselves:

  ```bash
  # bash (temporary, current shell)
  eval "$(hubenv completions bash)"
  # bash (system-wide)
  hubenv completions bash > /etc/bash_completion.d/hubenv

  # zsh (shellrc)
  echo 'eval "$(hubenv completions zsh)"' >> ~/.zshrc
  # zsh (fpath)
  hubenv completions zsh > "${fpath[1]}/_hubenv"

  # fish
  hubenv completions fish > ~/.config/fish/completions/hubenv.fish
  ```

- No **dynamic** completion (no `argcomplete`, no runtime introspection of
  the actual `argparse` tree).
- No **completion for `--flag` values** (only sub-commands; flags are not
  completed).
- No **`completions` for `--format`** (only the top-level verb and one
  level of sub-command).
- No **`--shell` flag** (positional only).
- No **script self-validation** (the script is trusted as generated).
